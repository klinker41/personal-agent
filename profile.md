# User Profile & Development Preferences

This document records core user habits, development preferences, and global
conventions across projects.

## Core Preferences
- **Language & Styling:** Clean, readable, idiomatic code. Use type annotations
  in Python and strict TypeScript where applicable.
- **Naming Conventions:** Use kebab-case (dashes, not underscores) for skill,
  rule, and sidecar names.
- **Formatting:** Format all Markdown files (`.md`) to a maximum line length
  of 80 characters.
- **Testing:** Write comprehensive unit and integration tests for new features
  and bug fixes. Verify before concluding tasks.
- **Git Discipline:** Perform iterative self-review before committing. Never
  run `git push` on main repositories unless explicitly instructed.
- **Web Services:** Prototype web services must run on port 4401.

## Communication Style
- Concise, direct, and action-oriented.
- Focus on practical implementations with transparent rationales.
